# Simulator patch, loading buffers.json into App.jsx

**One-time setup. Two edits to `App.jsx`. No other files change.**

---

## What this does

Replaces the hardcoded `SAFETY_RADIUS` constants in `App.jsx` with values
loaded at startup from `buffers.json`, which is generated by the OLF DLA
Dust Hazard Framework tool.

The simulator's `SAFETY_RADIUS` stores values in **pixels**.
`buffers.json` stores values in **km** plus pre-converted pixel values.
The loader reads the pre-converted pixel values directly, no math needed in `App.jsx`.

Zone → asset class mapping:

| Dust hazard zone | Simulator asset class | Rationale |
|---|---|---|
| Core exclusion   | `pad`     | Landing pads are primary sources, innermost zone |
| Buffer           | `habitat` | Habitats are sensitive long-duration assets |
| Buffer           | `rover`   | Rovers operate in the field |
| Coordination     | `solar`   | Solar panels distributed widely |

---

## Step 1, Drop buffers.json into the simulator's public folder

```
lunar-simulator/
└── public/
    └── buffers.json   ← put it here
```

The Vite dev server will serve it at `/buffers.json`.

---

## Step 2, Add the loader hook in App.jsx

Find this block near the top of `App.jsx` (around line 189):

```js
// Safety radii in real km, these are the pixel sizes that gameplay was
// tuned around, expressed honestly in km using the corrected scale.
const SAFETY_RADIUS = {
  pad:     7.22  * PIXELS_PER_KM,   // ~17.5 px
  solar:   2.89  * PIXELS_PER_KM,   // ~7 px
  habitat: 14.43 * PIXELS_PER_KM,   // ~35 px
  rover:   1.44  * PIXELS_PER_KM,   // ~3.5 px
};
```

Replace it with:

```js
// Safety radii, loaded from buffers.json (OLF DLA Dust Hazard Framework).
// Falls back to original hardcoded values if buffers.json is absent.
// Values in pixels: PIXELS_PER_KM = 700 / 288.678 ≈ 2.4248
const SAFETY_RADIUS_DEFAULT = {
  pad:     7.22  * PIXELS_PER_KM,
  solar:   2.89  * PIXELS_PER_KM,
  habitat: 14.43 * PIXELS_PER_KM,
  rover:   1.44  * PIXELS_PER_KM,
};
let SAFETY_RADIUS = { ...SAFETY_RADIUS_DEFAULT };

// Async loader, runs once at startup, updates SAFETY_RADIUS in place.
// buffers.json must be in public/ so Vite serves it at /buffers.json.
(async function loadBuffers() {
  try {
    const res = await fetch('/buffers.json');
    if (!res.ok) throw new Error(`buffers.json not found (${res.status})`);
    const data = await res.json();
    if (data?.SAFETY_RADIUS) {
      SAFETY_RADIUS = {
        pad:     data.SAFETY_RADIUS.pad     ?? SAFETY_RADIUS_DEFAULT.pad,
        solar:   data.SAFETY_RADIUS.solar   ?? SAFETY_RADIUS_DEFAULT.solar,
        habitat: data.SAFETY_RADIUS.habitat ?? SAFETY_RADIUS_DEFAULT.habitat,
        rover:   data.SAFETY_RADIUS.rover   ?? SAFETY_RADIUS_DEFAULT.rover,
      };
      console.log('[OLF] buffers.json loaded, SAFETY_RADIUS updated:', SAFETY_RADIUS);
      console.log('[OLF] Source site:', data._meta?.site ?? 'unnamed');
      console.log('[OLF] Zones (km):', data.zones_km);
      if (data.temporal) {
        console.log('[OLF] Advised ops clearance:', data.temporal.advised_clearance_fmt);
      }
    }
  } catch (e) {
    console.warn('[OLF] buffers.json not loaded, using default SAFETY_RADIUS.', e.message);
  }
})();
```

---

## Step 3, Verify

Start the dev server (`npm run dev`) and open the browser console. You should see:

```
[OLF] buffers.json loaded, SAFETY_RADIUS updated: { pad: ..., solar: ..., habitat: ..., rover: ... }
[OLF] Source site: Shackleton Rim Alpha
[OLF] Zones (km): { core: 4.97, buffer: 12.43, coordination: 24.85 }
[OLF] Advised ops clearance: T+2 hr  (lander mode only)
```

If `buffers.json` is missing or malformed, the simulator falls back silently to
the original hardcoded values, no crash, no broken gameplay.

---

## Notes

- `SAFETY_RADIUS` loads **asynchronously** before the React tree mounts.
  Because the loader runs in an IIFE before any gameplay state initialises,
  the values will be in place by the time the first render uses them.
  If you need to guarantee synchrony (e.g. hot-reloading edge cases),
  wrap the game init in a `useEffect` that waits for a `buffersLoaded` state flag.

- The loader overwrites `SAFETY_RADIUS` in module scope. Since `App.jsx` accesses
  `SAFETY_RADIUS` inside functions (not at import time), this works without any
  React state changes.

- To switch scenarios mid-session, call `loadBuffers()` again with a different
  `buffers.json` and trigger a game reset. (Hook 3 in the integration roadmap.)

- `buffers.json` is ignored by git if you add `public/buffers.json` to `.gitignore`,
  which keeps generated scenario files out of the simulator's repo.
